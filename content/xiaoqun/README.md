# 小群姐姐栏目 · 如何新增一期

每期一个 JSON 文件，放在本目录。文件名建议与 `slug` 一致，例如：

```
2026-10-06-ep1.json
2026-10-07-ep2.json
```

构建时 `lib/episodes.ts` 会读取全部 `.json`，按 `date`（再按 `episode`）倒序排列。首页「最新一期」取排序后的第一条；`/xiaoqun/[slug]` 用 `slug` 匹配。

## 字段说明

```jsonc
{
  "slug": "2026-10-07-ep2",          // URL 路径段，唯一
  "episode": 2,                       // 期数（数字）
  "date": "2026-10-07",               // YYYY-MM-DD
  "themes": [
    { "category": "主题分类", "title": "故事名（无书名号）" }
  ],
  "source_url": "https://mp.weixin.qq.com/s/...",
  "stories": [
    { "title": "故事名", "gist": "一两段大概……" }
  ],
  "questions_method": "用法: ……3个问题按「遇到什么问题→想到什么办法→结果怎样」排……",
  "questions": [
    {
      "story_title": "故事名",
      "items": [
        { "q": "问题？", "answer_hint": "答案落点" }
      ],
      "bonus": {                      // 可选：如果答得出再问
        "q": "附加问题？",
        "answer_hint": "答案落点"
      }
    }
  ],
  // 复述核心：每则故事一条（必填，每期都要写）
  "cores": [
    {

      "next_4_weeks": "接下来4周：……",
      "after_stage1": "一阶后面：……",
      "tools_this_week": "10工具本周N号：……"

    ],

        "短句节拍 1……",
        "短句节拍 2……"

```

### 复述核心规则 & `cores` 字段

- **长期规则（任何阶段都适用）**：每个故事的复述都要触及三个核心——主人公**遇到了什么问题**、**想到了什么办法**、**结果怎样**。它放在愿闻表达一阶规则之内：仍然只问 3 个主问题、只用 1 号工具「首先/然后/最后」、不问感想/观点、每天≤5分钟。
- `cores[]`：每则故事一条 `StoryCore`（`story_title` / `problem` / `solution` / `result`），只根据本期 gist、beats、问题里已有的事实写，每项一句话。页面第二部分会在该故事的问题前显示「复述核心」卡片。
- 结尾来自出版社简介、音频里还没核对时，加「以音频为准」。
- 没有明显冲突的诗意故事（如《蟋蟀的歌声》），不硬造冲突：用可选 `labels`（如「想做什么 / 发生了什么 / 最后怎样」）轻轻带过。
- 3 个主问题按核心顺序：Q1 问问题，Q2 问办法，Q3 =「用首先、然后、最后说说：遇到了什么问题、想到了什么办法、结果怎样。」（按故事自然改写），都附答案落点。附加题可保留。
- 示范稿：开场「大家好，我是____，我今天带来的故事是《……》。」之后 **首先（问题）→ 然后（办法）→ 最后（结果）**，句子短，5 岁孩子能跟讲。
- `stage.outline.core_rule`：写上面这条规则（不写时页面也会显示默认文案）。
- 邮件同样按这个结构：三问对应问题/办法/结果，示范稿首先/然后/最后对应问题/办法/结果。

### `transcripts` 字段

- 用途：听音频时家长扫一眼的**提炼要点**，不是绘本全文，也不是完整音频文案。
- 每则故事一条 `StoryTranscript`：`story_title`、可选 `note`、有序 `beats[]`。
- `note` 建议写「提炼要点·非绘本全文」并注明书名 + 小群姐姐公众号。
- `beats` 约 6–12 条，按听故事顺序；只保留关键名、规则、情节落点。

## 工作日例行流程（建议）

1. 从公众号拿到当日两则故事的大概与主题。
2. 写 `stories[].gist`（一两段大概）。
3. **写 `transcripts` 要点**（在 gist 之后）：每则 6–12 条跟听节拍，标注「提炼要点·非绘本全文」，并注明书名 + 公众号来源。勿粘贴绘本全文或完整音频文案。
4. **写 `cores`**：每则故事的「问题 / 办法 / 结果」各一句（只用已有事实；结尾来自简介时注「以音频为准」）。
5. 按愿闻式写 3 个主问题，对应 cores：Q1 问题、Q2 办法、Q3 首先/然后/最后串起问题→办法→结果；可选「如果答得出再问」（附答案落点）。
6. 更新 `stage`（项目第几天、本周工具号，保留 `outline.core_rule`）。
7. 写示范稿（填空名用 `____`）：首先（问题）然后（办法）最后（结果）。
8. 复制本目录某期 JSON 为模板 → 改字段 → 存为新文件。
9. 本地 `npm run dev` 打开 `/xiaoqun/<slug>` 检查；推送后 Vercel 自动构建。
10. 邮件给 Jing 时同样带上复述核心（问题/办法/结果）、对应的 3 问和示范稿。

**不要**改已发布期的 `slug`（分享链接会断）。改内容可以，改 slug 等于新页面。
